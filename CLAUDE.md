# CLAUDE.md — Tsundoku

## Project Overview

Tsundoku is a PWA for organizing personal book collections using a Kanban-style board. Users manage books across four stages: wishlist, unread pile (tsundoku), library, and to sell. Books can be added manually or via barcode scanning (ISBN lookup via Open Library). Available in French (default) and English, with light and dark mode support.

## Tech Stack

- **Framework**: Next.js 16 (App Router, Turbopack) + React 19 + TypeScript
- **Styling**: Tailwind CSS v4
- **Database**: Dexie.js (IndexedDB) — local-first, all data stored client-side
- **Cloud**: Supabase (Auth, Postgres, Storage) — OTP code auth, cloud sync, community catalog
- **PWA**: Serwist (configurator mode) — `serwist.config.js` + `serwist build` post-step
- **Drag & Drop**: @dnd-kit (core + sortable) — versions live in `package.json`
- **Animations**: motion
- **Barcode Scanning**: @zxing/browser
- **Image Cropping**: react-image-crop
- **Testing**: Vitest + @testing-library/react

## User-Facing Language

French (default) and English. Users switch language in Settings > Preferences. All UI strings use the `useTranslation()` hook from `src/lib/preferences.tsx`.

## Development

```bash
npm install

npm run build      # next build && serwist build
```

Environment variables (see `.env.example`):

## Project Structure

- `src/lib/` — domain logic: data layer (Dexie `db`, books CRUD, sync, backup), external lookup (Open Library, BnF, ISBN), and presentation helpers. `src/lib/i18n/` holds the dictionaries (`fr.ts` canonical, `en.ts`) plus locale types and the plural helper.
- `src/hooks/` — Dexie live-query hooks and viewport helpers.
- `src/components/` — reusable UI components.
- `src/app/` — App Router routes. `src/app/sw.ts` is the service worker (excluded from `tsconfig.json`, compiled separately by the Serwist CLI).
- `supabase/migrations/` — SQL migrations for the Supabase schema.

## Project-Specific Rules

- `sw.ts` is excluded from `tsconfig.json` (uses webworker types, compiled separately by Serwist CLI)
- Serwist must use configurator mode, not `withSerwistInit` wrapper (Next.js 16/Turbopack compat)
- `package.json` `overrides` lifts `zod@^4.0.0` to `^4.6.7` (GHSA-mrhx-c7xc-m3w5, fixed in 4.6.6). Every `@serwist/*` 9.5.x package pins `zod` to an exact vulnerable version, and no Serwist release (stable or the 10.0.0 previews) ships a patched pin, so `npm audit --omit=dev --audit-level=high` fails without the override. Remove it only once `npm view @serwist/next@<installed version> dependencies.zod` is 4.6.6 or later (`npm ls zod` cannot tell you: the override masks the pin)
- Dexie SSR guard: `typeof window !== 'undefined'`
- Supabase SSR guard: `supabase` client is `null` on server (same pattern as Dexie)
- Sync is local-first: Dexie remains source of truth, Supabase is backup/sync layer
- Community catalog contributions are anonymous — `community_books` has no `user_id`
- A user who sets `profiles.share_shelf = true` (migration 005, default `false`) exposes `title`, `author`, `cover_url`, `stage`, `is_reading` and `updated_at` for every one of their non-deleted books (`deleted_at IS NULL` — a soft-deleted book stamps `updated_at = deleted_at`, so without that filter it would sort first as the newest "public" entry) — nothing else, no ids, notes, prices or `user_id` — through the `public_shelf` view, which `anon` and `authenticated` may `SELECT`. `cover_url` is sanitised, not passed through: it can hold a Supabase Storage path keyed by the owner's auth uuid (`src/lib/covers.ts`'s `uploadCover`) or a raw base64 `data:` URL (`resolveCoverUrl`'s offline fallback), so the view only lets through a plain `https://` URL that isn't a Storage `covers/` path (`'https://%'`, not `'http%'`: the looser pattern let `http://` through — mixed content on an https page, so a broken image rather than the fallback — and anything merely starting with those four letters) — anything else becomes `''`, which the hub renders as the paper-rectangle-plus-initial fallback (Task 12), never a broken image or a leaked path. `share_shelf` is locked (migration 006): `authenticated` only holds column-scoped `UPDATE (contribute_to_catalog)` on `profiles`, so no one can flip it via the app or a REST call — it is set only from the dashboard SQL editor, uuid never committed. The view is also pinned to a `site_owner` table (RLS on, no policy, all grants revoked — unreadable to `anon`/`authenticated`): `public_shelf`'s `WHERE` now also requires `p.id IN (SELECT id FROM public.site_owner)`, so only the owner's shelf can ever appear. `site_owner` is created empty by 006 — the shelf is empty until, immediately after applying 006, you run `INSERT INTO public.site_owner (id) VALUES ('<owner auth uuid>');` in the dashboard SQL editor (uuid never committed). Widening the `SELECT` list, the join, or `site_owner` membership needs a review, not a quick edit. Migrations here have no CLI workflow (the `supabase` CLI is not part of this project's toolchain): apply a new file by pasting it into the dashboard's SQL editor, in filename order
- Book ids are client-minted strings, not uuids. `addBook` uses uuidv4, but `importBooks` preserves whatever ids the imported file carries, so any format can reach the cloud. `books.id` is therefore `text` (migration 004) — do not narrow it back to `uuid`: a non-uuid id makes Postgres reject the row with 22P02, a permanent 400 that strands the book on one device forever
- ISBN lookup is Open Library first, BnF second (`src/lib/book-lookup.ts`). Open Library returns JSON and cover images; BnF has legal-deposit coverage of French publishing that Open Library lacks — measured 2026-08-03, it resolved every French ISBN Open Library missed — but returns no covers and titles carrying cataloguing apparatus (`"Houris : roman ([Éd.] en grands caractères)"`), which is what `normalizeBnfTitle`/`normalizeBnfAuthor` exist to strip. `normalizeBnfTitle` needs `dc:creator` passed in: BnF does not always separate the statement of responsibility with `" / "`, so the only way to know `"… Les années ([Éd. en gros caractères]) Annie Ernaux"` ends at "années" is that the tail equals the creator. Do not promote BnF to primary, and do not add it to the title-search path without measuring first — its relevance ranking is poor (searching "boussole enard" returns a critical essay before the novel)
- `bnf.test.ts` asserts against SRU responses captured from the live API in `src/lib/__fixtures__/`, not only hand-written XML. The real records exposed the trailing-author case the synthetic ones hid. Keep both: the synthetic envelope covers the error paths, the captured one covers reality
- BnF responses are deliberately left cacheable by the service worker, unlike Supabase reads. Catalogue records are immutable, so a stale one is harmless — the `isSupabaseApiRequest` guard exists because a stale *pull* advances the sync cursor past unapplied rows, which has no analogue here
- Duplicate detection (`src/lib/duplicates.ts`) is exact, never fuzzy: it matches on canonical ISBN-13 or on accent- and punctuation-stripped title **and** author. It is advisory and never blocks adding, so a false positive is worse than a miss. `BookForm` takes `excludeBookId` for the same reason — in edit mode the book being edited must not be reported as a duplicate of itself
- Cover strategy: OL URL > user photo (cropped, max 400px JPEG) > generated SVG. Community catalog uses generated covers only
- Theme colors: paper `#FAF8F5`, forest `#2D4A3E`, amber `#C4956A`, cream `#F5F0EB`. Dark mode overrides via `[data-theme="dark"]` in globals.css
- **`DESIGN.md` is the project's design identity** (tokens and their roles, type scale, the amber = money-piles rule, the sanctioned italic column quotes, refused defaults). Read it before any visual change; `design-tells` and `design-critique` treat what it names as sanctioned
- **Deliberate identity**: a warm off-white paper ground (`--paper: #FAF8F5`) with a dark forest green as the primary ink/accent color (`--forest: #2D4A3E`), a muted amber as the sole secondary accent (`--amber: #C4956A`), and a cream surface tint (`--cream: #F5F0EB`) — read from `src/app/globals.css`. Dark mode swaps to a near-black forest ground (`--paper: #1A2B24`) with off-white ink (`--ink: #E8E2DB`), keeping the same amber accent. No purple/violet/indigo, no generic blue, no default Tailwind gray scale in the interface (generated book covers are exempt, see `DESIGN.md`)
- **Text color is a solid semantic token, never an opacity of forest.** Use `text-ink` (primary), `text-muted` (secondary), `text-subtle` (tertiary/placeholder), `text-faint` (decorative only — bullets, separators), `text-amber-ink` (amber as text or meaningful icon), `text-danger` (destructive/error). `text-forest/NN` for text is banned: composited on paper that scale ran 1.68:1–4.07:1, so every tier failed WCAG AA — the author line on each book card sat at 2.53:1. Alpha also cannot be tuned per theme, which is why light mode used to be the weaker of the two. `bg-forest/NN` and `border-forest/NN` for decorative fills are still fine; card boundaries use `border-border-subtle` / `border-border-strong`
- `contrast.test.ts` parses globals.css and asserts every token ≥4.5:1 against paper/surface/cream in **both** themes (`--faint` at the 3:1 non-text bar). Adding or retuning a token means it has to clear that test, which also carries a control asserting the replaced colors still fail
- Stage glyphs are SVG in `StageIcon.tsx`, not emoji. `STAGE_CONFIG` deliberately has no `emoji` field: it was the only label on the mobile tab bar, where 📚/📖 were indistinguishable. `StageTabs` stacks icon over label so the full "Livres à acheter" fits a ~93px tab; the label is 12px and wraps to two lines rather than shrinking or truncating (10px sat below the legibility floor for primary navigation)
- Keyboard focus comes from one global `:focus-visible` rule in globals.css. Do not add `focus:outline-none` without an equally visible replacement
- Form fields are ≥16px on touch devices (unlayered `@media (pointer: coarse)` rule in globals.css, so `text-sm` cannot beat it) and `html` carries `touch-action: manipulation`: iOS zooms into any focused field under 16px and an installed PWA has no chrome to zoom back out. Never cap `maximumScale` or set `user-scalable=no` in `layout.tsx` — pinch-zoom stays (WCAG 1.4.4); `zoom.test.ts` pins all of it
- Reduced motion needs both layers: the CSS `prefers-reduced-motion` block covers transitions/animations, and `MotionProvider` (`MotionConfig reducedMotion="user"`) covers the motion library's JS springs. CSS alone does not reach them
- i18n: homegrown, no dependencies. `fr.ts` defines the canonical shape, `en.ts` satisfies `Record<TranslationKeys, string>`. French and light mode are the defaults and there is **no** `prefers-color-scheme` detection — a deliberate opt-out from the portfolio default, because theme is a per-device preference persisted in Dexie (`db.settings` key `theme`) and toggled in Settings, and reading a media query would fight the stored value on first paint. Both themes are fully supported and `contrast.test.ts` asserts both.
- Content files (quotes, roadmap, changelog) are locale-indexed separately from the translation dictionary
- Fonts: Playfair Display (serif), Inter (sans)
- Bump the version in `package.json` (semver) when a commit changes user-facing behavior. Add a matching entry in `src/lib/changelog.ts`. Internal changes (refactors, tests, docs) don't trigger a bump.
- Supabase free tier auto-pauses projects after ~7 days of inactivity. A daily Vercel Cron (`vercel.json` → `/api/keepalive`) reads one row from `community_books` to keep the project active. `CRON_SECRET` on Vercel (Production scope only — preview deployments never run crons) authenticates the call; if it is missing or empty the route still pings and reports `authenticated: false`, because a strict check would reject Vercel's own scheduler (it sends no usable header without a secret) and silently disable the keepalive.
- First-visit routing (`src/lib/entry.ts`): `/` ships both surfaces in the server HTML (`data-surface="landing"` / `"app"`), a `<head>` hint script plus `EntryGate` pick one through `html[data-entry]`, and an unlayered rule in globals.css hides the other. `enteredApp` (a `db.settings` key) means "has entered the app": set when books exist or on the explicit enter action. The old `hasSeenWelcome` row is left in place, unread. To see the landing again, Settings › About links to `/accueil` (French) or `/en`: landing-only routes with no `EntryGate`, whose enter button navigates to `/`. `/accueil` is `noindex` with its canonical on `/`. Do not add a "preview" mode to `/` itself, because the gate, the hint script and the stored hint would all need to know about it. Never show the board by default while Dexie loads. A server cookie was rejected because it makes `/` dynamic, so no prerendered HTML in the precache and offline start breaks
- `public/landing/` and the manifest screenshots (`public/screenshots/`) are generated by `npm run screenshots` from `scripts/screenshot-seed.json` against a local `next start -p 9877` (build it with placeholder `NEXT_PUBLIC_SUPABASE_*` values, or the client throws and the page never loads), never hand-edited, and regenerated whenever the board UI changes visibly. `public/landing/**` is excluded from the service-worker precache in `serwist.config.js`. The script takes a locale (`npm run screenshots -- en`; no argument captures both): French keeps the bare names, English frames carry an `-en` suffix (`board-1440-light-en.webp`), and `LandingPage.tsx` picks the suffix from its `locale` prop, so a recapture in either locale needs no code edit. The manifest screenshots stay French, and their alt text (README) and label (web app manifest) live in `scripts/screenshot-seed.json`: the capture script rewrites the README alts from it and `manifest.ts` reads the labels, so describe a changed frame there, once
- Retention (migration 007): a book soft-deleted more than 30 days ago is *stripped*, not deleted, nightly by pg_cron (`purge_soft_deleted_books()`, the only place the period is set): title, author, notes, cover and every other content column are cleared, `purged_at` is set, and the row keeps `id`, `user_id`, `created_at`, `updated_at`, `deleted_at`. The tombstone must stay so that a device offline for over 30 days still pulls it and deletes its local copy (`pullRemoteChanges`) instead of pushing it back; a BEFORE trigger enforces the rule: a stale push (an edit whose `updated_at` is not newer than the delete) keeps a purged row deleted and stripped, a newer edit is a restore (`deleted_at` back to NULL, `purged_at` cleared), and a client role can never set or clear `purged_at` itself (only the SECURITY DEFINER purge does). The trigger never writes `cover_cleanup_queue` (it runs as `authenticated`, which has no rights on it). The app never stores or shows a tombstone (pull deletes locally, `public_shelf` filters `deleted_at IS NULL`). Deleting `storage.objects` rows in SQL leaves the files in the object store, so the purge only queues paths (covers-bucket URLs only, one statement with the strip) in `cover_cleanup_queue` and the daily `/api/purge-covers` cron (needs `SUPABASE_SERVICE_ROLE_KEY` + `CRON_SECRET`, server-only, fails closed, constant-time token compare, `maxDuration = 60` for Vercel Hobby) deletes them through the Storage API. `deleteAccount()` queues covers it could not remove (a failed `remove()`, a partial 200, a full 1000-file listing page) via `record_cover_leftovers` (own uuid prefix or `<uuid>/<file>.jpg` only, max 1000 paths) and returns `coversCleanup`: `removed`, `queued`, or `unqueued` when even the queueing failed, which Settings shows honestly. Before the first purge in production, count and export the tombstones (see the migration's header). Runbook for `coversCleanup: 'unqueued'` (covers left in Storage because even the queueing failed): the owner periodically sweeps covers-bucket folders that match no account, listing them in the SQL editor with `SELECT DISTINCT (storage.foldername(name))[1] AS folder FROM storage.objects WHERE bucket_id = 'covers' AND (storage.foldername(name))[1] NOT IN (SELECT id::text FROM auth.users);`, then deleting each folder through the Storage API or dashboard (never by `DELETE` on `storage.objects`)
- Privacy notice (`/confidentialite`, `/en/privacy`): the text is shared with William's other sites. `src/lib/privacy/*.json` are **vendored, byte-identical copies** of the canonical common, hosts and my-tsundoku files: refresh them with `cp`, never edit or re-serialise them here, and report a false sentence instead of rewording it. `notice.ts` walks the site file's `compose` list, resolves `[text](key)` links (site → common → hosts; https/mailto only, an unknown key throws at build) and never renders a section whose `status` starts with `pending` (the captcha section until Turnstile ships). The date line lives in `PRIVACY_COPY`; bump it with the text. `PRIVACY_PATHS` (`routes.ts`) duplicates the routes so the footer does not ship the JSON to the client; a test holds the two equal. Both pages are static and **deliberately precached** by the service worker (Serwist picks up every prerendered route), so the notice reads offline
- `next.config.ts` sends a static header baseline on every route (`frame-ancestors 'none'` as the only CSP directive, `nosniff`, `strict-origin-when-cross-origin`), hides `X-Powered-By`, and allowlists exactly two image hosts for `next/image`: `covers.openlibrary.org` and the host of `NEXT_PUBLIC_SUPABASE_URL` (derived, so a fork never allowlists someone else's project). Only BookConfirmation (Open Library search and scan results) goes through `/_next/image`; stored covers render `unoptimized`, so the allowlist cannot break an imported cover; `next.config.test.ts` pins the list
- Migration 008 (`supabase/migrations/008_hardening.sql`, applied by hand like the others) puts `CHECK` length limits on `books` and `community_books` (title 500, author 300, ISBN 20 characters), pins `search_path` on the three definer functions of 001/002, revokes `delete_own_account()` from `anon`, adds `owner_delete_community_book(uuid)` (definer, gated on `site_owner`, the owner's way to remove a bad catalogue row), and replaces every `storage.objects` policy that mentions the `covers` bucket with four own-folder policies (`<auth uid>/…`). A `storage.objects` policy that names no bucket is not touched and must be dropped by hand: the file's header has the query. `008_hardening.test.ts` runs migrations 001–008 in PGlite behind stand-ins for the Supabase roles, `auth.uid()` and `storage.objects`; each behaviour is first shown on the pre-008 schema, so a green run is not a harness that refuses everything. The client mirrors the limits (`BOOK_LIMITS` in `src/lib/book-validation.ts`, `maxLength` in BookForm), so an over-limit book is refused locally, on sync and on backup import alike (the rejection list names the book and the limit)
